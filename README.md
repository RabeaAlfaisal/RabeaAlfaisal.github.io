# متجر المكيفات — موقع استيراد وبيع مكيفات سبليت

موقع ثابت (static) بالكامل بدون خادم خلفي، جاهز للنشر على GitHub Pages. عربي بالكامل، تخطيط RTL، متجاوب مع الجوال.

## البنية

```
index.html            الصفحة الرئيسية (كتالوج + سلة)
css/style.css          تنسيقات الموقع
js/config.js            رقم الواتساب وإعدادات عامة
js/firebase-config.js   إعدادات Firebase (مشتركة بين الموقع ولوحة الإدارة)
js/app.js               منطق الكتالوج والسلة والطلب عبر واتساب (يقرأ من Firestore)
data/products.json      بيانات أولية (seed) فقط — لم تعد المصدر الحي للبيانات
assets/images/          صور المنتجات (يوجد placeholder.svg افتراضي)
admin/index.html         لوحة إدارة المنتجات (غير مرتبطة من التنقل، مستبعدة من robots.txt)
admin/admin.js           منطق لوحة الإدارة (يكتب مباشرة في Firestore)
firestore.rules          قواعد أمان Firestore جاهزة للنسخ إلى Firebase Console
robots.txt               يستبعد /admin/ من الفهرسة
```

## مصدر البيانات: Firestore وليس products.json

بعد الإعداد الأولي، أصبحت بيانات المنتجات الحية مخزّنة في **Cloud Firestore** (مشروع Firebase)، وليس في `data/products.json`.
الموقع العام يقرأ من Firestore مباشرة (فقط المنتجات غير المؤرشفة)، ولوحة الإدارة تكتب مباشرة إلى Firestore — لا حاجة لأي
Personal Access Token أو تعديل ملفات عبر GitHub.

يبقى `data/products.json` في المستودع كبيانات تمهيدية (seed) فقط: لوحة الإدارة فيها زر **"استيراد من data/products.json"**
يستورد هذه المنتجات النموذجية إلى Firestore أول مرة إن كانت القاعدة فارغة (لا يكرر منتجاً موجوداً بنفس id).

### إعداد Firestore (مرة واحدة)

1. في [Firebase Console](https://console.firebase.google.com)، افتح المشروع (هنا: `rabeaalfaisal`) → **Firestore Database** → أنشئ قاعدة بيانات (Native mode) إن لم تكن موجودة.
2. افتح تبويب **Rules**، انسخ محتوى ملف [`firestore.rules`](firestore.rules) كاملاً، الصقه، ثم اضغط **Publish**.
   - بدون هذه الخطوة تبقى القاعدة على `allow read, write: if false` الافتراضية ولن يعمل الموقع ولا لوحة الإدارة إطلاقاً.
3. افتح `admin/index.html` على الموقع المنشور واضغط **"استيراد من data/products.json"** لتعبئة القاعدة بالمنتجات النموذجية (اختياري، فقط أول مرة).

### ⚠️ ملاحظة أمان مهمة جداً

قواعد `firestore.rules` المرفقة تسمح بالقراءة **والكتابة العامة** لأي زائر — ليس فقط لمن يفتح `admin/index.html`،
بل لأي شخص يفحص كود الموقع ويستخرج منه إعدادات Firebase (وهي أصلاً قيم عامة تظهر في أي تطبيق ويب Firebase) ويرسل
طلبات مباشرة إلى Firestore. هذا مقصود لتبسيط الإدارة بدون نظام تسجيل دخول، **وليس حماية حقيقية**.

نفس منطق "الإخفاء وليس الحماية" ينطبق على صفحة `admin/index.html`: هي غير مرتبطة من قوائم الموقع ومستبعدة من
`robots.txt`، لكن أي شخص يعرف أو يخمّن الرابط يمكنه فتحها — والأهم أن الكتابة في Firestore ممكنة أصلاً بدون المرور
بهذه الصفحة أبداً طالما القواعد مفتوحة.

**للحصول على حماية فعلية لاحقاً:** فعّل Firebase Authentication (مثلاً بريد إلكتروني/كلمة مرور للمالك)، وأضف تسجيل
دخول في `admin/`، وغيّر في `firestore.rules`:

```
allow write: if request.auth != null;
```

ثم انشر القواعد المحدثة من نفس تبويب Rules.

## تعديل المنتجات

### عبر لوحة الإدارة (الطريقة الموصى بها)

1. افتح `<رابط موقعك>/admin/` (الرابط غير ظاهر في تصفح الموقع، افتحه مباشرة).
2. أضف منتجاً جديداً، أو اضغط "تعديل" على أي صف في الجدول لتحميل بياناته في النموذج.
3. **أرشفة** تُخفي المنتج من الكتالوج العام فوراً دون حذف بياناته (يظهر في اللوحة بعلامة "مؤرشف" فقط).
4. **حذف نهائي** يحذف المنتج من Firestore بالكامل ولا يمكن التراجع عنه.
5. أي حفظ ينعكس على الموقع العام خلال ثوانٍ (لا حاجة لإعادة نشر أو انتظار GitHub Pages، لأن القراءة تتم مباشرة من Firestore عند تحميل الصفحة).

### يدوياً عبر Firebase Console

يمكنك أيضاً فتح Firestore Database في Firebase Console وتعديل مستند أي منتج في مجموعة (collection) اسمها `products`
مباشرة — كل مستند معرّفه (Document ID) هو نفس حقل `id` في المنتج، وحقوله مطابقة لبنية `data/products.json`.

### تعديل products.json (للبيانات التمهيدية فقط)

عدّل `data/products.json` يدوياً إذا أردت تغيير مجموعة "البذور" التي يستوردها زر "استيراد" في لوحة الإدارة. تعديل هذا
الملف بعد الإطلاق **لن يغيّر** الكتالوج المعروض للعملاء، لأنه لم يعد يُقرأ مباشرة من الموقع.

## تغيير رقم الواتساب

افتح [`js/config.js`](js/config.js) وعدّل السطر:

```js
WHATSAPP_NUMBER_LOCAL: "0558742544",
```

اكتب الرقم بالصيغة المحلية السعودية `05XXXXXXXX` فقط — التحويل إلى الصيغة الدولية `9665XXXXXXXX` يتم تلقائياً في الكود.

## نشر الموقع على GitHub Pages

هذا المستودع مُعدّ للنشر من **جذر الفرع الرئيسي (root of `main`)**.

1. ادفع (push) هذا المستودع إلى GitHub.
2. من صفحة المستودع على GitHub: **Settings → Pages**.
3. تحت **Build and deployment → Source** اختر **Deploy from a branch**.
4. تحت **Branch** اختر الفرع `main` والمجلد **`/ (root)`**، ثم اضغط **Save**.
5. انتظر دقيقة أو دقيقتين، سيظهر رابط الموقع أعلى نفس الصفحة (بصيغة `https://<username>.github.io/<repo>/`).

بعد كل `git push` إلى `main` سيُعاد نشر الموقع تلقائياً خلال دقيقة تقريباً — لكن لاحظ أن تعديلات المنتجات عبر لوحة
الإدارة **لا تحتاج** إلى push أو إعادة نشر أصلاً، لأنها تُكتب مباشرة في Firestore ويقرأها الموقع في كل تحميل صفحة.

## جودة وإمكانية الوصول

- لا تعتمد الوظائف الأساسية (الكتالوج، السلة، الطلب عبر واتساب) على أي إطار عمل خارجي — HTML/CSS/JS عادي، مع استيراد Firebase SDK كوحدات ES module من CDN فقط لطبقة البيانات.
- السلة محفوظة في `sessionStorage` (تُمسح بإغلاق التبويب)، لا حسابات ولا تسجيل دخول للعملاء.
- كل الحقول والأزرار تحمل `label`/`aria-label` مناسبة، والصور تحمل نص `alt`.
- سلة فارغة تُعطّل زر "تأكيد الطلب عبر واتساب" تلقائياً بدل السماح بإرسال طلب فارغ.
